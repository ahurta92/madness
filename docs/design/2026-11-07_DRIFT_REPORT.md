## src/apps/madqc/README.md

- **D01 · Medium · Response schema describes the removed v2 output.** The [schema table](../../src/apps/madqc/README.md) (lines 336–340) describes a flat `response_properties[]` array with `property`, `component`, `freqB`/`freqC`, and `value`. The current writer produces `properties.response_properties.<property>.<protocol_key>[]`: alpha rows contain `omega`, `directions`, and an `alpha` matrix; beta rows contain `A`, `B`, `C`, `freq_b`, `freq_c`, and `beta`. Following the documented schema breaks result extraction. Evidence: [Applications.hpp](../../src/madness/chem/Applications.hpp), line 660; [response_metadata.hpp](../../src/apps/molresponse/solvers/response_metadata.hpp), line 224; [calc_executor.hpp](../../src/apps/molresponse/calc/calc_executor.hpp), line 2188; and the checked-in [He alpha reference](../../src/examples/qc/response_he_alpha/reference/response_he_alpha.calc_info.json). **Correction:** replace the flat-array schema with the emitted v3 structure; label the old shape as historical only if retained.

- **D02 · Medium · Unnamed SCF metadata promises fields that are not emitted.** The [SCF schema table](../../src/apps/madqc/README.md) (line 308) lists `elapsed_time`, `finished_at`, `git_hash`, `host`, `mpi_size`, and `nthreads`. [Applications.hpp](../../src/madness/chem/Applications.hpp), line 458, writes only `mpi_size`; [SinglePointDriver](../../src/madness/chem/Drivers.hpp), line 66, forwards that result without adding those fields. The [He reference](../../src/examples/qc/response_he_alpha/reference/response_he_alpha.calc_info.json) confirms this shape. The human summary also substitutes `0.0` seconds and one thread when the fields are absent ([ResultsSummary.hpp](../../src/madness/chem/ResultsSummary.hpp), line 242), so that display is not measured timing. **Correction:** document the actual metadata and identify additional provenance/timing as work for the unified layer.

- **D03 · Low · The advertised input-group list omits implemented groups.** The exhaustive-looking [CLI list](../../src/apps/madqc/README.md) (lines 96–97) omits `pcm` and `io`. `pcm` has a print-parameters branch in [madqc.cpp](../../src/apps/madqc/madqc.cpp), line 164. `IOParameters` is part of `Params` and implements backend and Dalton-directory settings ([ParameterManager.hpp](../../src/madness/chem/ParameterManager.hpp), lines 78 and 290); the response workflow consumes the backend selection in [madqc.cpp](../../src/apps/madqc/madqc.cpp), line 263. **Correction:** include both input groups and distinguish accepted groups from `--print_parameters` support: `io` currently has no branch in that dispatcher.

- **D04 · Low · Visualization discovery is not conditional on this run's plot settings.** The [guide](../../src/apps/madqc/README.md) (lines 394–395) says no manifest is written when no plot knobs were enabled. [VizManifest.hpp](../../src/madness/chem/VizManifest.hpp), lines 62–74 and 115, instead scans the existing output tree for every `.cube`, `.dx`, and `.dat` file and suppresses writing only when the scan is empty. Previous-run artifacts and unrelated `.dat` files can therefore appear even with plotting disabled. **Correction:** describe extension-based discovery and its lack of current-run provenance; do not promise that manifest entries were generated by the current calculation.

## src/apps/molresponse/calc/README.md

- **D05 · Medium · Warmup accounting is missing from the iteration/metrics contract.** The [README](../../src/apps/molresponse/calc/README.md) (lines 20 and 27) describes ES warmup and persisted metrics without defining how their costs relate. Warmup executes additional solver steps; downselection and TDA-to-Full promotion reset `iter` before the main solve ([build_response_ground_state.hpp](../../src/apps/molresponse/solvers/build_response_ground_state.hpp), lines 380, 410, and 467). The ES wall timer starts before ground preparation and warmup, while the checkpoint event counts main-solve iterations using `st.iter - iter_at_start` ([calc_executor.hpp](../../src/apps/molresponse/calc/calc_executor.hpp), lines 888, 998–1012, 1090, and 1256). Thus the iteration allowance/count excludes warmup while the solve wall time includes it. **Correction:** define main iterations, warmup work, and the timed interval explicitly so future convergence studies do not interpret their ratio as main-iteration cost alone.

## src/apps/molresponse/orchestrator/README.md

- **D06 · Medium · The ground-state fingerprint guarantee has an undocumented condition.** The [invariant](../../src/apps/molresponse/orchestrator/README.md) (line 17) says the archive fingerprint gate runs before restart reuse. In `run_response_with_ground`, it runs only when `in.archive_file` is nonempty ([response_workflow.hpp](../../src/apps/molresponse/orchestrator/response_workflow.hpp), line 267). A direct caller supplying an already prepared ground state and an empty archive path still reaches `mgr.run` and its restart reconciliation at line 341. **Correction:** state that the archive-backed path performs this gate and that an archive-free caller must establish compatibility before reusing `calc_dir`. This exception concerns the prepared-ground API; it does not establish a bypass in the named `madqc` path, which supplies an archive.

## src/apps/oep/README.md

- **D07 · Medium · Explicit convergence criteria can override the claimed `each_energy` addition.** The [invariant](../../src/apps/oep/README.md) (line 14) says `each_energy` is added whenever absent. The driver appends it to a local vector but installs that vector with `set_derived_value` ([oep.cc](../../src/apps/oep/oep.cc), lines 118–123). User-defined values take precedence over derived values ([QCCalculationParametersBase.h](../../src/madness/mra/QCCalculationParametersBase.h), lines 257–260). A deck explicitly setting `convergence_criteria` without `each_energy` therefore keeps that omission. **Correction:** describe the addition as a derived default, with explicit user criteria taking precedence. An unconditional requirement would need a separate implementation decision.

## src/madness/chem/README.md

- **D08 · Medium · The nonmutation guarantee does not cover both residual overloads.** The [metric invariant](../../src/madness/chem/README.md) (line 60) says residual/density routines copy their operands so reporting cannot mutate caller-owned trees. The two-input residual overload does copy, but the existing-residual overload directly calls `norm2s(world, residuals)` ([FunctionResidual.h](../../src/madness/chem/FunctionResidual.h), lines 14–27). `norm2s` can reconstruct shared functions when their tree state does not admit a direct coefficient sum ([vmra.h](../../src/madness/mra/vmra.h), lines 909–936). Values are preserved, but tree representation need not be. **Correction:** limit the guarantee to the copying overload and density helper; document the existing-residual overload's tree-state side effect.

- **D09 · Low · Trace-change wording conflates collection identity with orbital correspondence.** The [trace invariant](../../src/madness/chem/README.md) (line 61) invokes per-function correspondence and orbital identity while citing `function_metric_trace_change`. That helper computes the absolute difference of two unweighted traces and checks collection layout; unitary rotations within the same compared collection do not require orbital-by-orbital alignment. Elementwise correspondence belongs to the separate `function_metric_absolute_change` helper ([FunctionMetricSummary.h](../../src/madness/chem/FunctionMetricSummary.h), lines 50–54, 75–102). **Correction:** require the same physical state/reference, representation, sampling convention, and comparable collection for trace changes; reserve orbital correspondence for elementwise changes. Do not treat equal dimensions alone as proof of physical compatibility.

- **D10 · Medium · Fixed intermediate work is stated more broadly than the SCF entry points implement.** The [convergence invariant](../../src/madness/chem/README.md) (line 62) says intermediate rungs consume their supplied iteration cap. That is the behavior of `rung_exit` when its caller sets `final_protocol=false` ([ConvergenceSettings.h](../../src/madness/chem/ConvergenceSettings.h), line 234). SCF supplies `!checkpoint_observer || !has_next_supplied_rung` for this flag ([SCF.cc](../../src/madness/chem/SCF.cc), line 3198), so an unnamed/standalone SCF run without the observer treats even intermediate rungs as eligible for early convergence. **Correction:** scope the fixed-work statement to the participating named SCF and response paths, and document the unnamed SCF exception. Making this uniform remains an implementation decision for the unified convergence layer.
